The mechanism

It has to predict what it was never shown.

This is the whole trick, and it is why the engine cannot bluff its way to a stamp. A rule that merely fits the data you handed it is worth nothing — overfitting is free. So the engine never gets to grade its own homework.

01 / SPLIT

Show 12 terms. Hide 8.

The engine sees only the shown prefix. The held-out terms exist, are known, and are withheld — the same protocol every time, fixed before the run, not chosen after seeing what worked.

02 / RECOVER

Find the shortest exact rule.

Minimum description length over a constrained hypothesis space, in exact rational and integer arithmetic. No floats on the stamping path — anything past 253 where a float would silently lie is refused instead.

03 / SURVIVE OR ABSTAIN

Predict all 8 exactly, or get nothing.

Not "close." Not "within tolerance." Exact integer equality on every held-out term, or the engine abstains and says so. A wrong rule fails here — which is precisely how it caught itself three times. Watch it run →

The limit, stated in numbers

On real operational text, it certifies about 9% of the sentence.

Not a footnote — the measurement. Given a realistic logistics summary, certify verified the arithmetic 4200 / 1400 = 3 and left the sentence a human would actually act on — "Unit Bravo has 3 days of fuel" — sitting in the uncertified remainder. Coverage: 0.09.

That is the honest shape of the tool. Every claim kind it supports is self-contained — checkable from the claim text alone. None of them compares a claim against an external table, so the operational sentence is exactly the one it cannot reach. Anyone selling this as a gate over arbitrary AI output is overstating it, including its author.

ReachesArithmetic, percentages, primality, gcd/lcm, modular and date arithmetic, aggregates, closed forms, and sequence continuation — each provable from the text itself.
RefusesAnything needing outside knowledge, ambiguous evidence, floats past 253, or work over budget. Refusal is the designed output, not a failure.
Needs a second stageGrounding a claim against a real ontology — exact comparison of (entity, field, value), REFUSED where no ground truth exists. That belongs beside the gate, not inside it.

The receipts

This engine has lied. Here is exactly when, and what it cost to fix.

Every project claims rigour. The only evidence that means anything is what happened the day the claim failed — so the failures are published in full, with the defect, the wrong number, and the commit that repaired it. All of it is still in the log.

What went wrong

  • A002275, repunits. Stamped VERIFIED. Predicted 111111112740; OEIS says 111111111111. Found on the harness's first ever external run — after ~5,070 internal cases had passed clean.
  • The cause was the promise itself. The held-out check was comparing with a 1e-6 relative tolerance while the documentation promised exact equality. At a(n) ≈ 1010 that forgives an error of ~104.
  • A002203, companion Pell. A float holonomic fit with 6 free parameters scored shorter than the true order-2 recurrence and cleared the window it happened to match. Predicted 551612; OEIS says 551614.
  • 2026-07-11. The first full keyword:core sweep surfaced 3 more. Fixed at root the same night.

What it changed

  • Exact arithmetic became structural. Coefficients snap to exact rationals; the tolerance is gone — held-out comparison is integer equality or nothing.
  • An exact rule can no longer be masked by a float overfit. When any candidate reproduces the surface exactly in integer arithmetic, the non-exact path is dropped from selection outright.
  • The repairs cost zero correct stamps. The 109-sequence sweep was re-run on the fixed engine: 44 verified, all externally correct, 0 false. A001147 moved from false-stamp to exactly verified.
  • Nothing was quietly amended. A retraction commit stands in the log for a novelty claim that turned out not to be novel.

Each of those was caught by a gate doing its job against data the author does not control. That is the only reason the zero is worth anything — and it is why the external battery runs against live oeis.org rather than a table shipped in the repository.

How to contribute Run the gates yourself

Can I test it first?

Yes. Use the live claim checker, run the public demo core, and grade the published frozen outputs against public ground truth yourself.

Does the demo see my data?

Everything in the browser runs locally. There is no managed service: the claim checker and full-engine mode call an engine you run yourself with primus-serve, so your input never leaves your machine unless you point it somewhere.
